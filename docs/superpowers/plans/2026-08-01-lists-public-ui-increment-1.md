# Public Lists UI — Increment 1 (Shared Foundation) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the five shared pieces that books' and games' public list pages both depend on, with nothing user-visible changing except a `robots` meta tag on games.

**Architecture:** Four of the five pieces are additive and independent — a new column plus its callback, a new model scope, and two new ViewComponents. The fifth adds a helper and two attributes to the games layout `<head>`. Nothing here reads or renders a list page; increments 2 and 3 consume all of it.

**Tech Stack:** Rails 8.1, Minitest + fixtures + Mocha, ViewComponent, Tailwind CSS 4 + DaisyUI 5, PostgreSQL.

Spec: `docs/superpowers/specs/2026-08-01-lists-public-ui-design.md`. Branch `lists-public-ui` is already checked out with the spec committed.

## Global Constraints

- **Run every command from `web-app/`.** Docs live at the project root, not `web-app/docs/`.
- **Lint is `bundle exec standardrb`**, never `bin/rubocop`. `--fix` autocorrects.
- **Never run `bin/brakeman`.**

- **No code comments** unless this plan shows one explicitly.

### Task 1: `lists.activated_at` column, callback, and backfill

Users want "recently added" to mean recently *activated*. `created_at` is when a list was submitted — lists sit pending for months and a newly-added list can be over a year old. `updated_at` is bumped by any edit. No historical activation date exists in either database (legacy `ranked_lists.created_at` records RC rebuilds, legacy `changesets` only cover `Book`, legacy PaperTrail `versions` begin 2025-06-28), so existing rows are backfilled from `updated_at` and the column is exact from here on.

The column and callback live on the shared `List`, so all four domains inherit them. Only books and games surface the value.

**Files:**
- Create: `db/migrate/<timestamp>_add_activated_at_to_lists.rb`
- Modify: `app/models/list.rb` — add the callback beside the existing `before_save :auto_simplify_content` (around line 55) and the private method beside `auto_simplify_content` (around line 125)
- Modify: `db/schema.rb` (regenerated by `db:migrate`, commit the diff)
- Test: `test/models/list_test.rb`

**Interfaces:**
- Consumes: nothing.
- Produces: `List#activated_at` (`ActiveSupport::TimeWithZone` or `nil`), stamped on every transition into `active`. Task 4's `Lists::CardComponent` reads it. Increments 2 and 3 sort on it.

```ruby
class AddActivatedAtToLists < ActiveRecord::Migration[8.1]
  def up
    add_column :lists, :activated_at, :datetime
    add_index :lists, :activated_at

    # status 3 is the `active` enum value. No historical activation date exists in
    # either database, so updated_at is the best available approximation for rows
    # that predate this column.
    execute "UPDATE lists SET activated_at = updated_at WHERE status = 3"
  end

  def down
    remove_column :lists, :activated_at
  end
end
```

The comment is a deliberate exception to the no-comments rule: `3` is a magic number and the backfill's rationale is not recoverable from the code. `up`/`down` rather than `change` because `execute` is not reversible.

### Task 2: `List.search_text` scope

Public list search covers name, source and url — the three fields the legacy site searched. This is a **new** scope rather than a widening of `search_by_name`, which `Admin::ListsBaseController#apply_search_filter` uses: admin search semantics should not change as a side effect of a public feature.

1,044 books lists and 152 games lists make `ILIKE` free. There is no `List` OpenSearch index in this app and this does not need one.

**Files:**
- Modify: `app/models/list.rb` — add beside the existing `search_by_name` scope in the `# Scopes` block (around line 70)
- Test: `test/models/list_test.rb`

**Interfaces:**
- Consumes: nothing.
- Produces: `List.search_text(query)` → `ActiveRecord::Relation`. Returns `all` when `query` is blank. Increments 2 and 3 call it as `where(list_id: List.search_text(query).select(:id))`.

Replace `app/components/lists/weight_breakdown_component.rb` entirely:

```ruby
# frozen_string_literal: true

class Lists::WeightBreakdownComponent < ViewComponent::Base
  def initialize(ranked_list:)
    @ranked_list = ranked_list
  end

  private

  attr_reader :ranked_list

  def details
    @details ||= ranked_list&.calculated_weight_details
  end

  def penalties
    details["penalties"] || []
  end

  def base_weight
    pct(details.dig("base_values", "base_weight"))
  end

  def final_weight
    pct(details.dig("final_calculation", "final_weight"))
  end

  def total_penalty
    pct(details.dig("final_calculation", "total_penalty_percentage"))
  end

  def quality_bonus
    return nil unless details.dig("quality_bonus", "applied")

    before = details.dig("quality_bonus", "penalty_before")
    after = details.dig("quality_bonus", "penalty_after")
    return nil if before.nil? || after.nil?

    pct(before - after)
  end

  def pct(value)
    return nil if value.nil?
    number_with_precision(value, precision: 1, strip_insignificant_zeros: true)
  end
end
```

`strip_insignificant_zeros` is what turns the JSONB's `5.0` into `5` and leaves `60` as `60`.
