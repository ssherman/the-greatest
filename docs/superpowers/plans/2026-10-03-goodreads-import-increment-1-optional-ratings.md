# Optional Review Ratings (Goodreads Import, Increment 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A book review may have text and no star rating, everywhere reviews are written, stored, counted and shown.

**Architecture:** `reviews.rating` becomes nullable, guarded by a new check constraint (a rating or a body), and the model validation matches. The summary aggregate counts only rated reviews, so averages are unaffected. Every display surface stops assuming a rating exists: the book page summary line and reviews card, a single review, the "Rate this book" widget and its modal, `/my/reviews`, and the admin review pages.

**Tech Stack:** Rails 8.1, PostgreSQL check constraints, ViewComponent, Stimulus, Minitest + fixtures, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-03-goodreads-import-design.md` §8 (and §2, decision "Reviews with text but no rating").

## Global Constraints

- Run every Rails command from `web-app/`. Lint is `bundle exec standardrb`, never `bin/rubocop`.
- Only `Books::Book` includes `Reviewable` (verified 2026-10-03), so music and games are unaffected; do not add guards for them.
- The constraint is `rating IS NOT NULL OR body IS NOT NULL`. The existing `reviews_body_not_blank` and `reviews_rating_range` constraints stay unchanged (`rating >= 1 AND rating <= 5` passes when `rating` is NULL).
- When present, a rating is an integer 1–5. A review needs a rating or a body. A body that the sanitizer reduces to nil does not count as a body.
- `ratings_count` = `COUNT(rating)`. `ratings_sum`, the five `rating_N_count` buckets and `text_reviews_count` keep their current definitions.
- An unrated review shows **no stars** (not an empty star track). `rating DESC/ASC` sorts put unrated reviews **last** (`NULLS LAST`).
- The book page is edge-cached: `Reviews::WidgetComponent` must render identical HTML for every visitor when `review` is nil. Do not change that path.
- There is no JSON-LD anywhere in `app/` (verified 2026-10-03). The spec's "structured data" bullet has nothing to change; do not add JSON-LD in this increment.
- Migrations: run with `ANNOTATERB_SKIP_ON_DB_TASKS=1` (annotaterb rewrites 100+ unrelated headers on this machine). The dev database is shared with other worktrees; this change is backward compatible for them (a nullable column and a constraint every existing row satisfies). Update the three schema-annotation headers that mention `rating` by hand.
- Minitest 6: never `assert_equal nil, x`; use `assert_nil`. `assert_equal [5, 2, nil], array` is fine.
- No warnings in `bin/rails test` output beyond the two known upstream sources.

## Review Focus

1. **A book whose only reviews are unrated.** The summary row has `ratings_count: 0`, `text_reviews_count: 1`. Today `CardComponent#render?` and `SummaryLineComponent#render?` gate on `rated?`, so the written review would be invisible. Expected: the card shows "No ratings yet" plus the review; the summary line shows "1 review" with no stars. Tests: Task 3.
2. **A user clears the stars on a review that has no text.** Expected: refused (422), rating unchanged; the modal's own check stops it before the request. Tests: Task 4 (controller), Task 6 (E2E).
3. **A body that sanitizes to nothing** (whitespace only, or an image-only paste) **with no rating.** Expected: invalid, nothing saved. Test: Task 1.
4. **`/my/reviews` counts with an unrated written review.** `MyReviewsStats#rating_only` is `total - written` today, which goes wrong once `written` includes unrated reviews that `total` excludes. Expected: rated, written and rating-only counts each stay true. Test: Task 5.
5. **The widget's accessible label for an unrated review.** `widget_controller.js` would print "Your rating: null out of 5 stars". Expected: "Reviewed without a rating" both server-rendered and after hydration. Tests: Task 4 (component), Task 6 (E2E reads the label).
